# Ali Manbang Agentic Car

这是一个面向货运仿真环境的司机找货智能体方案。系统在一个自然月内持续为司机选择接单、等待或空驶调度等动作，目标是在提升月度净收益的同时，尽量满足不同司机的个性化偏好。

## 偏好解析是怎么做的

我们的偏好处理没有按司机 ID 写死规则，而是把运行时可见的中文偏好文本编译成结构化规则，再让策略层统一执行。

整体流程是：

1. 从司机状态里读取当前可见偏好。
   偏好文本会和罚金额度、罚金封顶一起进入解析流程。偏好只在运行时读取，不依赖线下固定司机配置。

2. 先分类，再抽字段。
   解析器把每条偏好拆成两个模型调用：第一步只判断规则类型，第二步只抽取该类型需要的字段。这样可以降低一次性让模型“理解、分类、计算、输出”的不稳定性。

3. 规则类型是有限枚举。
   支持的类型包括连续休息、固定安静时段、拒接货物品类、城市过滤、城市接单天数目标、距离上限、整天休息、每日接单节奏、位置边界、禁入圆形区域、必接指定货、每日回家、定时事件、月内到访点等。无法用可见信息执行的偏好会进入 `unknown`。

4. 模型只负责语义理解，不负责仿真计算。
   模型输出人能读懂的日期、时钟、坐标、距离、次数等原始字段；分钟偏移、跨天时间、坐标半径、硬约束/软偏好、默认值和异常值都由代码做确定性归一化和校验。

5. 高风险偏好更保守。
   如果偏好罚金高，解析时会优先使用更谨慎的推理模式。低置信度、字段缺失、格式不合法或连续解析失败时，不强行编译，而是标记为高风险未知偏好。

6. 策略层执行结构化规则。
   结构化规则会参与三个位置：决策前的强制动作，例如休息、回家、赴约；货源候选过滤，例如城市、品类、距离、时间窗冲突；最终动作保护，例如模型想接一个已经被过滤的货，或者空驶动作会违反距离/位置约束时，改成等待或其他安全动作。

7. 未知偏好有兜底审查。
   对高罚但没编译出来的偏好，会再用保守审查器检查候选货源和拟执行动作。明显安全才放行；不确定时宁可过滤或等待，避免为了短期收益触发大额偏好罚分。

这个设计的核心取舍是：让模型做中文语义解析，让代码做可验证的业务执行。它比硬编码每个司机更能适应偏好文案变化，也比完全交给模型直接决策更容易控制风险。

## 没做好的地方和止步原因

止步的主要原因是长期动态规划没有做好。

我们对偏好解析、候选货过滤、动作兜底做得比较重，短期内能避免很多明显违规动作。但月度仿真真正难的地方在于跨天、跨周、跨司机目标的长期规划：什么时候该为了未来高价值货等待，什么时候该主动空驶换市场，什么时候该提前安排整天休息，什么时候该牺牲一单收益来满足后续回家、赴约、到访点或城市天数目标。

现有方案更像“规则保护下的短视滚动决策”：每轮会基于当前候选货、当前状态和部分历史做选择，但没有把整个月的问题建成稳定的动态规划或全局调度问题。结果是局部动作经常看起来合理，月末回看却会出现目标完成太晚、休息日安排被动、区域迁移不够主动、等待和空驶节奏不够精细的问题。

所以我们止步不是因为偏好文本完全解析不了，而是长期收益和偏好之间的动态权衡没有形成足够强的全局规划能力。这也是后续最值得补的一块：把月度目标、未来货源分布、司机当前位置、休息债务、事件窗口和偏好罚分统一放进一个更明确的长期优化框架里。
